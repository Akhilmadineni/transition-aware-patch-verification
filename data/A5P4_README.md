# A5P4 - Transition-aware verification of AI-generated security patches

**Track:** Track 6  
**Application:** Infrastructure security patches for cloud environments

> This dataset is synthetic, generated by gen_author5.py with seed 2080. It must be described as synthetic in any publication.

## Simulated scenario

LLMs generate IaC patches that remediate cloud misconfigurations (open ingress, wildcard IAM, public buckets, weak TLS). Most pass a static check of the final planned state, but applying them goes through intermediate states: resource replacement without create-before-destroy, reordered rule removal/addition, and eventually-consistent policy propagation can briefly expose resources or cause outages. Each row is a patch with plan-level features; ground truth is the outcome of a transition-aware verification (replay in a sandbox).

## How it was generated

- Transient exposure ~ Bernoulli(sigmoid(z_exp)) and transient outage ~ Bernoulli(sigmoid(z_out)), each calibrated (~19% / ~15% before final-state override); both keep linear main effects (rule removals, eventual consistency, parallelism, explicit depends_on, generator, destroy count, dependents, live connections, replacement without create-before-destroy) plus the structures below.
- Regime: replacing a resource without create-before-destroy causes exposure for fail-open types (k8s NetworkPolicy, bucket, VPC-endpoint, WAF: absent = allow) but an outage for fail-closed types (security group, NACL, IAM, KMS, DB params: absent = deny).
- Saturation: fail-closed replacement outage risk grows with tanh(log live connections) and saturates for busy resources; TLS-listener replacement adds a dedicated outage term.
- Conjunction: rule churn opens an exposure gap only when rules are both removed AND added AND steps can race (no explicit depends_on with parallelism > 1).
- Threshold x interaction: eventual-consistency propagation keeps the old permissive policy live only above a score of ~0.6 and only when the patch tightens permissions.
- Threshold: IAM/KMS over-tightening (> 6 permissions removed) breaks callers; unordered parallel apply (parallelism >= 10) with >= 5 dependents races into outages.
- Final-state insecurity: 60% when the static check fails; when it passes, risk ramps up as permission delta rises above ~+2 (semantic broadening the check misses) and is U-shaped in generator confidence (over-confident > 0.97 or unsure < 0.6).
- Latent sub-population: ~5% of targets have unmanaged drift (console edits) that raises both exposure and outage risk regardless of plan features.
- Exposure window ~ LogNormal growing with eventual consistency.
- Noise: 5% Gaussian, ~0.7% outliers (live connections, LOC), 1-3% missing (eventual consistency, live connections, confidence).

## Target / label columns

- `verification_outcome` (5 classes; ~66% safe, ~12% transient_exposure, ~9% transient_outage, ~7% final_state_insecure, ~6% transient_exposure_and_outage).
- Binary view: `verification_outcome != 'safe'` (~34% unsafe).
- `exposure_window_s` (regression on non-zero rows).

## Suggested experiments

1. Transition-risk classification: predict unsafe vs safe (F1, PR-AUC) and full 5-class outcome (macro-F1); baselines = static final-state check only and a logistic model on plan features (transition risk is regime/conjunction-driven, so non-linear models should do clearly better).
2. Prioritised verification: rank patches by predicted risk and measure unsafe patches caught at a fixed sandbox-replay budget (recall@k).
3. Exposure-window regression for patches flagged as transient_exposure (R2 on log scale).
4. Generator comparison: unsafe rate and calibration of generator_confidence per generator_model.

## Notes

- Realism noise: ~5% Gaussian measurement noise on numeric signals, 1-3% missing values in a few columns, ~0.5-1% gross outliers in a few columns. Label/target columns are never noised by the measurement-noise step (they carry their own stochasticity).
- All IDs, sites, regions and assets are synthetic; no real people, companies, IPs or CVEs.
- The dataset contains inputs and ground truth only - no results of any proposed method.
